5  Landing page

The landing page is the front door of your training. It introduces the training as a whole, and helps visitors decide whether to register, or which training instance to open.

The figure below shows the parts of the landing page, and the names this guide uses for them.

In this chapter, you will learn how to:

  • Switch off template mode
  • Change the title and subtitle
  • Add or remove logos
  • Edit the information cards
  • List your training instances
  • Set up the hero buttons
  • Change the banner image
  • Edit the footer

Before you start

Everything in this chapter happens on the main branch, and almost all of it in the four data files in the data folder:

Data file What it holds
data/course.yml The title, description, learning outcomes, keywords and topics of your training
data/team.yml The people behind the training
data/instances.yml The list of training instances
data/website.yml Logos, button texts, the banner image and the footer

Work as described in Regular workflow: start the preview with python scripts/preview.py, make your changes, save them, and check them in your browser. You don’t have to commit after every change: you can make several changes, and commit and push them together.

If you’re not sure how a data file works, see Data files.

At the end of the chapter, a cheat sheet box sums up which file to open and what to change. It is handy when you come back to the guide later.

5.1 Switch off template mode

Your repository starts as a copy of the template, so it still presents itself as the template. You can see this in the yellow Want to use this template? banner at the top of the landing page (see overview image above). Switching off template mode turns your repository into your own training. Do this first:

  1. On the main branch, open data/website.yml.

  2. Find the line:

    template: true

  3. Change it to:

    template: false

  4. Save the file (Cmd+S (macOS) or Ctrl+S (Windows and Linux))

This changes two things:

  • The yellow banner disappears from the landing page.
  • The README, CITATION.cff and .zenodo.json now describe your training, using your data files. While template mode was on, they described the template itself.

Done when: the yellow banner is gone from the preview.

Replace the README

Your repository’s README, the description shown on its main page on GitHub, still describes the template. Replace it with the README for a training:

  1. In the Explorer panel, open the docs folder and then _template-README.md.
  2. Select all text (Cmd+A or Ctrl+A) and copy it.
  3. Open README.md in the main folder of your repository, select all text, and paste, so the copied text replaces it.
  4. Delete the note at the top of the file, between <!-- and -->, and the line starting with > **Template:**.
  5. Fill in the parts marked Write this yourself. The other parts, between <!-- generated:... --> lines, are filled in automatically from your data files.
  6. Save the file.

5.2 Change the title and subtitle

The hero is the large dark banner at the top of the landing page. It is the first thing visitors see, and shows the title and subtitle of your training, the logos and the buttons.

  1. Open data/course.yml.

  2. Find the lines:

    title: "Training title"
subtitle: "Training subtitle"

  3. Replace the text between the quotation marks with the title and subtitle of your training.

  4. Save the file.

The title is also used as the title of your website in the browser tab, in the README and in the citation of your training.

Tip

Keep the subtitle to one sentence, and start it with an action verb such as Learn, Understand, Explore, Build or Apply. For example:

Learn how to apply open science practices throughout the research lifecycle.

The subtitle is optional: to leave it out, change it to subtitle: "".

5.3 Add or remove logos

The logos in the hero show the organisations behind your training. You can add logos, remove them, or replace them with your own.

Add a logo

  1. Save your logo as an SVG or PNG file.

    Tip

    Use a white version of your logo, or one made for a dark background, so it stands out against the dark hero.

  2. Copy the file into the img/logos folder: drag it from your computer onto the folder in the Explorer panel in VS Code.

  3. Open data/website.yml and find the hero part:

    hero:
  logos:
    - src: "img/logos/SciLifeLab_Logotype_NEG.png"
      alt: "SciLifeLab"

  4. Add your logo at the bottom of the list. Copy the two lines of an existing logo, from - src: to alt:, and paste them below. Then change the values:

    • src: where the file is, starting with img/logos/, followed by the file name;
    • alt: the name of the organisation. Screen readers read this out for visitors who can’t see the logo.

    For example:

    hero:
  logos:
    - src: "img/logos/SciLifeLab_Logotype_NEG.png"
      alt: "SciLifeLab"
    - src: "img/logos/my-organisation.svg"
      alt: "My organisation"

  5. Save the file.

The logos appear in the same order as in the list.

Note

Keep the spaces at the start of each line exactly as in the example: the - src: line of every logo starts at the same position, and alt: lines up with src:.

The file name in src must match the name of your file exactly, including capital letters and the extension (.svg or .png).

Remove a logo

  1. Open data/website.yml and find the hero part.
  2. Delete both lines of the logo you want to remove: the - src: line and the alt: line below it.
  3. Save the file.
  4. Optional: if you no longer need the logo file, delete it from the img/logos folder. In VS Code, right-click the file and choose Delete.

5.4 Edit the information cards

The information cards below the hero describe your training. They are created from your data files:

Card Comes from
Training content description in data/course.yml
Learning outcomes learning_outcomes in data/course.yml
Keywords keywords in data/course.yml
Topics covered topics in data/course.yml (optional)
Founders People with the role Founder in data/team.yml
Contributors People with the role Contributor in data/team.yml

The same information is also used in the README and the citation of your training, and helps people find it in Zenodo and training registries such as TeSS.

Training content

  1. Open data/course.yml and find description:

    description: |
  Description of the content of the training.

  Lorem ipsum dolor sit amet, consectetur adipiscing elit...

  2. Replace the example text below description: | with a description of your training. Keep the two spaces at the start of every line. Separate paragraphs with an empty line.

The | after description: lets you write several lines and paragraphs. You can also use simple formatting, such as **bold** or links: [link text](https://example.org).

Tip

Focus on what the training covers. Around ten sentences is usually enough.

Learning outcomes, keywords and topics

These three are lists: each line starting with - is one item.

  1. Open data/course.yml and find learning_outcomes, keywords or topics:

    learning_outcomes:
  - "Learning outcome 1"
  - "Learning outcome 2"
  - "Learning outcome 3"

  2. Replace the example text between the quotation marks with your own.

  3. To add an item, copy a whole line, paste it below, and change the text. To remove an item, delete its whole line.

The learning outcomes are numbered automatically on the website.

Tip
  • Learning outcomes describe what participants will be able to do after the training. For guidance, see the SciLifeLab Training Hub resources on writing learning outcomes.
  • Keywords: around four or five short terms that describe the main subject areas. They help people find your training.
  • Topics: short phrases, not full sentences, that give visitors a quick overview of what the training covers.

The Topics covered card is optional. To leave it out, replace the list with an empty one:

topics: []

Founders and contributors

The Founders and Contributors cards list the people in data/team.yml:

  • Founders started the training, or are responsible for it.
  • Contributors contributed materials or expertise.

Each person looks like this:

- given_names: "Firstname1"
  family_names: "Lastname1"
  roles:
    - Founder
  affiliation: "Institution or organisation"
  orcid: ""
  citation_author: true
  1. Open data/team.yml.
  2. Fill in the details of each person:
    • given_names and family_names: first name(s) and surname. Put words like “van der” in the surname.
    • roles: Founder or Contributor.
    • affiliation: the organisation the person works for.
  3. To add a person, copy a whole entry, from - given_names: to the last line before the next - given_names:, paste it below, and change the values. To remove a person, delete their whole entry.

Each card is left out when nobody has that role. The other fields, such as orcid, email, course_contact and citation_author, are used for the citation of your training. They are explained in FAIRification and in the comments at the top of data/team.yml.

Important

Every person needs given_names, family_names, roles and affiliation. If one is missing, the preview shows an error that names the person and the missing field.

5.5 List your training instances

The All training instances banner near the bottom of the landing page has a button for each training instance. Visitors use it to open the website of the current training, or of an earlier one.

The list comes from data/instances.yml. Each training instance looks like this:

- slug: "2605"
  label: "May 2026"
  status: current
  visible: true
  show_in_hero: true
  instance_url: "./2605/"
  registration_url: "https://example.org/registration"
  sort_key: 202605
Field What it means
slug The year and month of the training instance as YYMM, the same as in its branch name. For example, "2605" for the branch release-2605
label The text on the button, for example "May 2026"
status current for the training instance that is running now or coming up next; previous for earlier ones
visible true to show the button in the banner; false to hide it
show_in_hero Only for the current training instance: whether the hero shows a button to it. See Set up the hero buttons
instance_url The link to the website of the training instance: "./YYMM/", with the same digits as slug
registration_url Only for the current training instance: the link to its registration page
sort_key The year and month as YYYYMM, for example 202605. Used to put the training instances in order
Important
  • Exactly one training instance has status: current. All others have status: previous.
  • The current training instance always has visible: true.
  • Each training instance has its own slug: never use the same one twice.
  • slug and instance_url use the same four digits.

If one of these rules is broken, the preview shows an error that explains what to fix.

Remove the example training instances

The template’s list contains example training instances, such as 2505 and 2411, that don’t exist in your repository. Their buttons would lead to pages that don’t exist. Start by removing them:

  1. Open data/instances.yml.
  2. Delete the whole entry of each example instance, from - slug: to sort_key:, except the one with slug: "0000".
  3. Save the file.

Keep the 0000 entry for now: it links to the example training instance on the release-0000 branch. You replace it once your first own training instance is ready.

Add a training instance

Each training instance has its own release- branch, with its own website. Adding it to instances.yml puts a button to that website on the landing page.

Note

Creating a release- branch does not add it to this list automatically. First create the branch, as described in Training instances, and then add it here.

  1. Open data/instances.yml.
  2. Copy a complete entry, from - slug: to sort_key:, and paste it at the top of the list, directly under instances:.
  3. Change slug, label, instance_url and sort_key to the new training instance.
  4. If the new training instance is now the current one, see Change the current training instance below.
  5. Save the file.

For example, for a training instance in November 2026:

- slug: "2611"
  label: "November 2026"
  status: current
  visible: true
  show_in_hero: true
  instance_url: "./2611/"
  registration_url: "https://example.org/registration"
  sort_key: 202611
Note

Keep the spaces at the start of each line exactly as in the existing entries: - slug: is indented by two spaces, and the other lines of the entry by four.

Change the current training instance

When a new training instance becomes the current one:

  1. In data/instances.yml, find the training instance that is current now, and change its status and show_in_hero:

    status: previous
show_in_hero: false

  2. Find the new current training instance, and set:

    status: current
visible: true
show_in_hero: true

  3. Save the file.

For example:

instances:

  - slug: "2611"
    label: "November 2026"
    status: current
    visible: true
    show_in_hero: true
    instance_url: "./2611/"
    registration_url: "https://example.org/registration"
    sort_key: 202611

  - slug: "2605"
    label: "May 2026"
    status: previous
    visible: true
    show_in_hero: false
    instance_url: "./2605/"
    registration_url: ""
    sort_key: 202605

Show or hide an earlier training instance

You may not want to show every earlier training instance on the landing page. To hide one, set its visible to false:

visible: false

To show it again, set it back to true. A hidden training instance stays in the list, and its website stays online: only its button disappears from the banner.

Warning

Never hide the current training instance with visible: false. To remove its button from the hero, use show_in_hero: false instead. See Set up the hero buttons.

Change the text on a button

Change the label of the training instance, for example from "May 2026" to "Spring 2026". This only changes the text visitors see, not where the button leads.

Change the order

The current training instance is always shown first. The earlier ones follow, newest first, sorted by sort_key. You don’t need to put the entries in order yourself, as long as each sort_key is the year and month of its training instance, written as YYYYMM: for example, 202605 for May 2026.

5.6 Set up the hero buttons

The hero can show two buttons:

  • Take me to the current instance opens the website of the current training instance.
  • Register now opens the registration page of the current training instance.

Both buttons use the training instance with status: current in data/instances.yml. See List your training instances to set which one that is.

Add the registration link

  1. Open data/instances.yml and find the training instance with status: current.

  2. Replace the example link in registration_url with the link to your registration page or form:

    registration_url: "https://your-registration-page.example"

  3. Save the file.

Hide the registration button

When registration has closed, or your training doesn’t need registration, empty the link of the current training instance:

registration_url: ""

The Register now button disappears. To show it again, fill in the link again.

Hide the current instance button

When there is no current training instance to point to, for example when your training is self-paced or not given at the moment, set show_in_hero of the current training instance to false:

show_in_hero: false

The button disappears from the hero. The training instance stays in the All training instances banner.

Change the button texts

You can change the text on the buttons, and the heading of the All training instances banner, without changing where they lead:

  1. Open data/website.yml and find the labels part:

    labels:
  hero_view_current_label: "Take me to the current instance"
  hero_registration_open_label: "Register now"
  instances_band_title: "All training instances"

  2. Change the text between the quotation marks. For example:

    hero_view_current_label: "Go to the latest training"
hero_registration_open_label: "Sign up"

  3. Save the file.

5.7 Change the banner image

The All training instances banner shows a decorative image next to the buttons. You can replace it with an image that fits your training.

  1. Copy your image into the img/images folder: drag it from your computer onto the folder in the Explorer panel in VS Code.

    Tip

    Use a landscape image. The image is cropped automatically to fill the space, so keep the important part near the middle.

  2. Open data/website.yml and find:

    instances_band:
  image: "img/images/navet-band.png"

  3. Replace navet-band.png with the file name of your image, for example:

    instances_band:
  image: "img/images/my-training-banner.jpg"

  4. Save the file, and check the preview at different widths of your browser window.

To show no image at all, set image: "".

TipIs the important part of your image cut off?

You can choose which part of the image stays visible. This is the only change in this guide in styles.css, the file that controls the look of the website, so make it carefully:

  1. Open styles.css and search for .instances-band__image (Cmd+F or Ctrl+F).

  2. In that block, find:

    object-position: center;

  3. Change center to the part you want to keep. For example, center top keeps the top of the image, and 30% center moves the visible part to the left.

5.8 Edit the footer

The footer at the bottom of the landing page shows who runs the training, its licence, how the website was built, and a link to your repository on GitHub. All of it is in the footer part of data/website.yml.

Organisation

Change organisation to the name of the organisation, programme or group responsible for your training:

organisation: "SciLifeLab Training Hub"

Licence

The licence tells others how they may reuse your training. The footer shows its name, linked to the page that explains it:

licence:
  name: "CC BY 4.0"
  url: "https://creativecommons.org/licenses/by/4.0/"
Important

The licence also appears in reuse in data/course.yml, where it’s used for the README and the citation. If you choose another licence, change it in both files, so they say the same, and replace the text in LICENSE.md. See FAIRification for help choosing a licence.

Repository link

The GitHub logo in the footer links to your repository. Replace url with the address of your repository on GitHub:

repository:
  url: "https://github.com/your-organisation/your-repository"
  image: "img/logos/Github_Neg.png"
  alt: "GitHub repository"

You find the address in your browser’s address bar when you open your repository on GitHub, for example https://github.com/SciLifeLab-Training/introduction-to-r.

Important

The repository link is required. The template also uses it to work out the address of your website, for the citation of your training.

Built with

The built_with part credits the SciLifeLab Training Webpage Template. You can usually leave it as it is.
