5  Landing page

You are now ready to make the template your own. In this chapter, we start with customizing the landing page, which is the front door of your training. It introduces the training as a whole, and helps visitors decide whether to register, or which training instance to open.

The figure below shows the parts of the landing page, and the names this guide uses for them.

In this chapter, you will learn how to:

  • Switch off template mode: replace the README and remove the template banner.
  • Customise the look: the organisation logos, the button texts, and banner image.
  • Describe your training: the title, subtitle, information cards, footer, and how others may reuse your training.

How to create a training instance and add it to the landing page is explained in the next chapter, Training instances.

Before you start

Everything in this chapter happens on the main branch, and almost all of it in three data files in the data folder:

Data file What it holds
data/course.yml The title, description, learning outcomes, keywords and topics of your training, and the organisation and licence shown in the footer
data/team.yml The people behind the training
data/website.yml Template mode, logos, button texts and banner image

Not sure how a data file works? See Data files.

Work as described in Regular workflow:

  1. In a new terminal, start the preview:
   python scripts/preview.py
  1. Make your changes, save them, and check the result in your browser.
  2. Commit and push your changes. You don’t have to do this after every change: you can make several changes, and then commit and push them together.

The cheat sheet at the end of this chapter sums up which file to open and what to change for each part of the landing page.

5.1 Switch off template mode

Your repository starts as a copy of the template, so it still presents itself as the template, in two places:

  • the README.md file, the description shown on your repository’s main page on GitHub, which still describes the template instead of your training;
  • the yellow Want to use this template? banner at the top of the landing page (see the overview image above).

In this section, you replace the README and then switch off template mode, so your repository presents your own training.

Replace the README

The template comes with a ready-made README for your training, in docs/_template-README.md. Copy it over the current README, which describes the template:

  1. In the Explorer panel, open the docs folder and then _template-README.md.

  2. Select all text (Cmd+A or Ctrl+A) and copy it.

  3. Open README.md in the main folder of your repository, select all text, and paste, so the copied text replaces it.

  4. Delete the note at the top of the file, between <!-- and -->, and the line starting with > **Template:**.

  5. Fill in the parts marked Write this yourself. The other parts, between <!-- generated:... --> lines, are filled in automatically from your data files.

  6. Save the file.

Remove the template banner

  1. Open data/website.yml.

  2. Find the line:

    template: true

  3. Change it to:

    template: false

  4. Save the file with Cmd+S (macOS) or Ctrl+S (Windows and Linux).

This changes three things:

  • The yellow banner disappears from the landing page.

  • The generated parts of your new README now show your training’s details, from your data files.

  • CITATION.cff and .zenodo.json now describe your training instead of the template.

NoteOptional: delete the template files you no longer need

Now you have switched off template mode, two things on your main branch are not needed any more:

  • The docs/_template-README.md file
  • The entire _template folder

You can delete both: in the Explorer panel, right-click each and choose Delete.

NOTE: Keep the rest of the docs folder!

NOTE: Deleting these means you cannot switch template mode on again (by setting template: true), the preview will then stop with an error, because the _template folder is missing.

Tip

The README shows the details you have filled in so far. Did you not fill in the data files yet? No problem: the README updates by itself every time you change them.

5.2 Customise the look

You can make the landing page your own by changing the organisation logos, the button texts and the banner image. All of these are in data/website.yml. Open it, and work through the parts below.

Logos

The logos in the hero show the organisations behind your training.

Add a logo

  1. Save your logo on your computer as an SVG or PNG file.

    Tip

    Use a white version of your logo, or one made for a dark background, so it stands out against the dark teal of the hero.

  2. Copy the logo file into the img/logos folder: drag it from your computer onto the folder in the Explorer panel in VS Code.

  3. In data/website.yml, find the hero part:

    hero:
   logos:
      - src: "img/logos/scilifelab-neg.png"
      alt: "SciLifeLab"
      height: 56
      primary: true

  4. Add your logo below the existing one, with these lines:

    • src: where the file is: img/logos/ followed by the file name;
    • alt: the name of the organisation;
    • height (optional): the height of the logo in pixels, 56 if you leave it out.

    For example:

  5. Save the file, and check the preview. If the logos look like different sizes, adjust their height until they look about the same.

The logo with primary: true (SciLifeLab) is always shown on the right. Your other logos appear to its left, in the same order as in the list.

Remove a logo

  1. In data/website.yml, delete all lines of the logo you want to remove, from - src: to its last line.

  2. Save the file and check the preview, the logo should be gone from the landing page.

  3. Optional: if you no longer need the logo file, delete it from the img/logos folder. In VS Code, right-click the file and choose Delete.

Button texts

You can change the text on the two hero buttons, and the heading of the All training instances banner:

  1. In data/website.yml, find the labels part:

    labels:
  hero_view_current_label: "Take me to the current instance"
  hero_registration_open_label: "Register now"
  instances_band_title: "All training instances"

  2. Change the text between the quotation marks. For example:

  3. Save the file, check the preview.

Note that this only changes the texts. Where the buttons lead, and when they are shown, is set in data/instances.yml: see Training instances.

Banner image

The All training instances banner shows a decorative image next to the buttons. You can replace it with an image that fits your training.

  1. Copy your image into the img/images folder: drag it from your computer onto the folder in the Explorer panel in VS Code.

    Tip

    Use a landscape image. The image is cropped automatically to fill the space, so keep the important part near the middle.

  2. In data/website.yml, find:

    instances_band:
  image: "img/images/navet-band.png"

  3. Replace navet-band.png with the file name of your image, for example:

  4. Save the file, and check the preview at different widths of your browser window.

To show no image at all, change it to image: "".

TipIs the important part of your image cut off?

You can choose which part of the image stays visible. This is the only change in this guide in styles.css, the file that controls the look of the website, so make it carefully:

  1. Open styles.css and search for .instances-band__image (Cmd+F or Ctrl+F).

  2. In that block, find:

    object-position: center;

  3. Change center to the part you want to keep. For example, center top keeps the top of the image, and 30% center moves the visible part to the left.

5.3 Describe your training

What the landing page says about your training comes from two data files: data/course.yml describes the training, and data/team.yml the people behind it. The information you enter in these files is also used in the README and the citation of your training, and helps people find it in Zenodo and training registries such as TeSS.

Both files contain explanations at the top and between the fields, in the lines starting with #. This section covers the main points; the explanations in the files give the details.

The training: course.yml

Open data/course.yml and work through the fields below, from top to bottom. You only change the values: the text after the colon. See Data files for how a data file is built and the different types of data values.

Important

Data files are very sensitive to layout:

  • Keep the number of spaces (indentation) at the start of each line exactly as they are. They show which information belongs together.
  • Keep the quotation marks around values.

If the preview shows an error after you save a data file, check these first. The error message usually names the file and the line.

Field Where it appears What to fill in
title The hero, and the browser tab The name of your training
subtitle The hero, below the title One sentence about the training (optional)
description The Training content card What the training covers, in a few paragraphs
learning_outcomes The Learning outcomes card What participants can do after the training
keywords The Keywords card Four or five short terms that describe the subject
topics The Topics covered card The main topics, as short phrases
language, target_audience, expertise_level, organizers, funding Not on the landing page: in the README, the citation and the information for training registries See the explanations in the file
licence, licence_url (under reuse) The footer (“Licensed under …”), the README and the citation CC BY 4.0 by default.

The other fields under reuse can stay empty for now:

  • doi, release_date and zenodo_communities belong to publishing your training on Zenodo, and are explained in FAIRification.
  • licence_id, website_url and preferred_citation can stay empty for most trainings. The template works out the address of your website, and creates the citation from your team, title and DOI.

For example, this is data/course.yml filled in for a made-up training, Introduction to R. The explanations starting with # are left out, so the whole file fits on one screen:

After saving the file, the preview shows the landing page with this information.

Tip
  • Subtitle: keep it to one sentence, and start it with an action verb such as Learn, Understand, Explore, Build or Apply.
  • Learning outcomes describe what participants will be able to do after the training. For guidance, see the SciLifeLab Training Hub resources on writing learning outcomes.
  • Optional fields: to leave out the subtitle, use subtitle: "". To leave out the funding, keep funding: [].
  • Licence: if you change it, also replace the text in LICENSE.md in the main folder of your repository with the full text of your new licence.

The team: team.yml

The Founders and Contributors cards at the bottom of the landing page list the people in data/team.yml. They are also credited in the README and the citation of your training.

Open data/team.yml and fill in each person. The comments at the top of the file explain every field. To add a person, copy a whole entry, from - given_names: to the line before the next person, paste it below, and change the values. To remove a person, delete their whole entry.

Important

Every person needs given_names, family_names, roles (Founder or Contributor) and affiliation. If one is missing, the preview shows an error that names the person and the missing field.

NoteRoles and authors

roles says what someone did: it is shown on the landing page and in the README. citation_author says whether they are an author of the training. Everyone is an author, unless you set citation_author: false. Only authors end up in the citation. On Zenodo, authors are listed as “creators”, and everyone else as “contributors”.

After saving the file, the Founders and Contributors cards on the landing page show the new team:

The team is also used for the citation of your training. Open CITATION.cff, .zenodo.json or README.mdin the main folder of your repository: the template has updated these from your data files, while the preview was running.
